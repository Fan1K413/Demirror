# Demirror 检测准确度增量研究

日期：2026-08-19
范围：Windows、CPU、默认离线、单图分析；本轮只做候选筛选和实验设计，不修改网页分数、阈值或运行时策略。

## 1. 结论

本轮已经完成第一优先 FerretNet 的离线资源探针和第一道有标签淘汰筛选，结论是：**FerretNet 被淘汰，不接入产品。**

- FerretNet 与现有 CLIP 语义、频域和整图纹理通道的出发点不同，主要检查局部像素依赖和纹理连续性；官方实现规模约 1.06M 参数、2.38 GFLOPs，适合 CPU 有界筛选。
- 官方源码、checkpoint、预处理和完整状态张量已经闭合：固定源码提交、checkpoint 4.09 MiB、89/89 张量严格加载、1,057,777 参数。
- 12 张无标签资源探针的分数在重复运行中完全一致；峰值工作集为 327–353 MiB，p95 为 2.73–2.88 秒。160 张全量筛选中峰值为 427–563 MiB，p95 为 1.25–1.31 秒，均通过资源门禁。
- 但在冻结的 80 张更新生成图上，官方 0.5 操作点原图仅命中 1 张、JPEG-85 命中 0 张；对现有五通道共同漏检的生成图新增命中均为 0。因此生成召回、每生成器切片和新增命中三项门禁全部失败。
- 该结果与公开榜单不矛盾：它说明公开基准上的平均表现不能替代 Demirror 的新生成器和传播条件门禁。由于已经硬性失败，不再为它重选阈值、裁切、投票、集成或继续测试 WebP／缩放／截图变体。
- LOTA 可列为第二候选。它的生成图准确率更高，但实拍准确率更低，而且主要依赖低位平面，预计更容易受 JPEG、截图和平台转码影响，也可能与现有 SAFE／Community 信号相关。
- LOTA 已完成源码和 CPU 适配预检，但还没有进入检测器评分：官方 `test.py` 强制 CUDA，且
  `model(pretrain=False)` 在该固定版本中仍会请求下载 ImageNet 骨干。隔离适配器在不修改上游
  源码的情况下临时关闭该下载，成功构造 23,510,081 参数网络并完成一次合成输入 CPU 前向；
  当前峰值工作集约 392 MiB、前向约 0.16 秒。这只证明可构造性，不是检测性能。
- 官方 README 只给出百度网盘权重位置，未见独立权重许可或稳定文件 SHA-256。因此不下载
  第三方镜像、不加载未登记 checkpoint，也不开始任何有标签评分。预检记录见
  [LOTA CPU 预检审计](../records/2026-08-19/pixel/lota_cpu_preflight_audit_v1.json)。
- Effort、GAPL、DFFreq、GlobalForge 和 FIND 暂不进入本地完整实验：原因分别包括模型过重、CPU 路径不明确、代码或权重许可不清、稳定官方实现尚未发布，或需要重新训练。

因此，本轮没有找到可安全加入计分的新模型；验证了一个可复用的、比单看论文准确率更严格的候选淘汰流程。

机器记录：[FerretNet CPU 探针与第一道淘汰审计](../records/2026-08-19/pixel/ferretnet_cpu_probe_audit_v1.json)。完整逐图输出留在 Git 忽略的 `outputs/research/`，并由此记录中的 SHA-256 绑定。

资源探针最初的输出虽然未写出 `label` 字段，但错误保留了带 `fake/`／`real/` 目录名的相对路径。该缺陷不影响模型严格加载、耗时、内存或随后固定阈值的有标签淘汰结果，但不满足“无标签输出”契约。v2 协议已移除该路径字段，并在相同 12 张、相同两视图和两次重复下重新验证；本报告只采用 v2 的资源结论。

## 2. 当前系统仍存在的问题

### 2.1 分布漂移仍是主要漏检来源

2026-08-12 的来源隔离确认窗中，现有五通道对较新生成器的原图召回为 68.75%，JPEG-85 为 66.25%。DDA 在这批生成器上的召回只有 15% 左右，NPR 也几乎没有新增命中。这说明旧生成器上学习到的上采样、频率或纹理痕迹会随生成架构变化，不应通过简单降低阈值补救。

### 2.2 现有 AI 分数不是概率

当前综合分是带相关性预算的证据分：不同模型按登记阈值贡献固定分值，相关像素模型只有最强通道取得完整权重，其余通道共享补充分。这个设计能限制同类模型重复加分，但它不是经代表性现实分布校准的后验概率。

在实拍来源家族、现代生成器和传输变体仍不足时，不应把 60 分解释为“60% 概率”，也不应为了让输出更像概率而直接训练新的融合器。此前六分数逻辑融合虽然提高了生成召回，也把实拍命中明显抬高，已经证明单个确认窗上的拟合不能解决来源漂移。

### 2.3 原图和 JPEG-85 仍不足以代表真实传播

AIGIBench 与 RRBench 的共同结论是：JPEG、裁切、缩放、社交平台传输，以及屏幕／打印后再拍，会显著改变被动检测器表现。Demirror 现有冻结实验主要覆盖原始解码和 JPEG-85，尚不足以判断截图、WebP、缩放和再数字化后的可靠性。

为使下一候选不再临时生成变体，2026-08-19 已按固定协议把 OpenFake 确认窗的 160 个源图
逐张材料化为 JPEG-85、WebP-85、长边 1024 缩放后恢复的 PNG、长边 1600 截图式 PNG，形成
640 个派生视图（约 598.85 MiB）。每个文件在写盘后重新校验 SHA-256、RGB 解码和 EXIF／ICC／
XMP 缺失；输出清单不包含标签、生成器名或来源目录，并以原始资源 SHA-256 保留源图簇绑定。
完整性复核已通过 640/640。派生图只代表可重复的传输代理，不能代替真实平台转码、屏摄或
打印再拍，也不包含任何模型分数。

现有 DDA、SAFE、forensic CLIP、Community Forensics、Nonescape Mini 随后对一个固定截图式
PNG 分别完成隔离 worker 探针，五路均可用，单路耗时约 9.63–18.33 秒。这只证明已有的输入
边界没有把 PNG 传播视图拒之门外；单张、无标签探针不得解释为任一通道在截图上的召回、误报
或稳定性。全量传播审计必须按模型保持独立进程、增加可恢复的批量检查点，避免每张图反复加载
大型 DDA 模型造成十余小时的无边界运行。

Community Forensics 已先完成此类全量审计。开始批量评分前，它在一个固定截图式 PNG 上与网页
现有隔离 worker 得到完全相同的分数（绝对差 0），因此批量路径只作为既有运行时的等价加速，
不是另一个模型实现。随后在冻结的 160 个源图及五种视图上完成 800 次评分；打分阶段不读取标签，
标签只在所有分数写入后用于既登记阈值的汇总。高置信阈值下，原图、JPEG-85 和截图式 PNG 都只
命中 3/80 生成图，缩放恢复 PNG 命中 2/80；上述四种视图对 80 张实拍均为 0/80。WebP-85 的
原始高置信命中为 7/80，但静态 WebP 不具备产品高置信资格；其有限复核阈值同时命中 15/80
生成图和 2/80 实拍。它既不能支持降低阈值，也不能证明“零实拍命中”可推广到现实分布；反而
确认了该通道在当前更新生成器上的高置信召回很低。完整协议与结果分别见
`research/records/2026-08-19/pixel/community_propagation_audit_protocol_v1.json` 与
`community_propagation_audit_v1.json`，两者均明确 `deployment_eligible=false`。

Nonescape Mini 使用相同的来源清单、变体清单与“先等价、后批量”的门禁。其批量实现逐项复现
网页 worker 的 EfficientNet-v2-S、严格 safetensors 加载、`Resize(256)`、中心裁切、JPEG-100
重编码和 ImageNet 归一化；固定截图探针与隔离 worker 的绝对分差同为 0。800 个视图的既登记
高阈值汇总显示：原图与截图式 PNG 各命中 34/80 生成图，JPEG-85 与缩放恢复 PNG 各 35/80，
WebP-85 为 37/80；但原图、JPEG-85、缩放恢复 PNG 和截图式 PNG 各有 5/80 实拍越过该阈值，
WebP-85 为 7/80。它提高了这一确认窗的生成命中，却没有保持旧 Projective Geometry 留出集所见
的零实拍命中。由于 OpenFake Web 实拍也只是一个窄来源，结果既不能量化总体误报，也不能支持
继续把“零误报补充通道”外推为产品保证。完整协议与结果分别为
`research/records/2026-08-19/pixel/nonescape_propagation_audit_protocol_v1.json` 和
`nonescape_propagation_audit_v1.json`；二者均禁止改变产品阈值、分数、依赖与网页策略。

forensic CLIP 的批量路径也与其隔离 worker 在固定截图视图上完全等价。它按当前已冻结的高阈值
和有限复核阈值完成 800 个视图：高阈值下，原图与截图式 PNG 都命中 15/80 生成图，JPEG-85
与缩放恢复 PNG 各 16/80，WebP-85 为 18/80；有限复核阈值依次为 26/80、28/80、28/80、
27/80、26/80。本确认窗 80 张实拍在两条阈值下均为 0/80。该结果证明该通道在这几种固定传播
代理下没有出现方向翻转，但其既有独立评估已记录约 6.7% 的高阈值实拍命中，不能用这一次零命中
覆盖旧证据，也不能增大权重。完整协议与结果分别为
`research/records/2026-08-19/pixel/forensic_clip_propagation_audit_protocol_v1.json` 和
`forensic_clip_propagation_audit_v1.json`，仍只授权离线观察。

SAFE 的首次批量实现于第 134/800 个视图安全停止：其中存在边长小于 256 像素的冻结图片，而产品
worker 对它们会返回不可用，v1 却把该输入条件升级为全局失败。v1 的协议、134 条无标签检查点和
失败原因均保留，不能解释结果。v2 禁止上采样这些图片，逐图写入 `unavailable / safe_input_too_small`，
并从对应固定阈值分母排除。等价探针仍为 0 差，最终每个视图可运行 158/160 张（80 生成、78 实拍）。
原图、JPEG-85 和 WebP-85 对更新生成图都是 0/80，高阈值只在缩放恢复 PNG 命中 2/80、截图式 PNG
命中 1/80；所有可运行实拍均为 0/78。该范围确认与 SAFE 已登记的“无损局部信号、跨生成器失败”
限制一致，不能给它增加权重或授权将重编码视图解释为强证据。记录分别是
`safe_propagation_audit_failure_v1.json`、`safe_propagation_audit_protocol_v2.json` 与
`safe_propagation_audit_v2.json`。

截至此处，四个可在约 0.3–0.7 GiB CPU 工作集内完成批量审计的像素通道得出互补但并不乐观的
结论：Community 对这批更新生成图的高阈值召回只有 2/80–3/80；SAFE 基本为 0/80；forensic CLIP
在传播代理下保持 15/80–18/80 的高阈值命中，但既有独立实拍评估并非零误报；Nonescape 命中
34/80–37/80，却在同一确认窗有 5/80–7/80 实拍命中。因此任何“多通道相加”都不能被当作独立
证据累积，也不支持事后降阈值。它们的价值在于明确了哪条通道的风险是现代生成器漏检、哪条是
来源迁移下的实拍误报，而不是制造一个看似更高的总分。

DDA 已完成补充传播审计所需的单图资源门禁。v1 在同一冻结截图视图上复现产品分数，绝对差为
0，但 Windows 虚拟环境启动器另启了后代解释器，原采样只覆盖启动器 PID，所得 5.3 MiB 工作集
无效；该结果已作废并单独保留失败记录。v2 改为每 50 ms 枚举启动器与全部后代、汇总工作集、越过
2 GiB 时终止整棵进程树；同一图片的有效峰值为 1,567,924,224 字节，分数仍为
`0.3888949155807495`，与既有产品探针差值为 0。

在该门禁通过后，DDA 以一个模型常驻、无并行检测器、逐图原子检查点完成 800 个冻结传播视图。
运行时重新比对同一截图式 PNG，批处理与产品分数绝对差仍为 0；父进程统计到 3 个进程、峰值
1,587,105,792 字节，未触发 2 GiB 止损。70 个视图因短边小于产品最小输入 336 像素而记为不可用，
不作上采样也不放入分母。固定的 0.94 高阈值下：原图生成图 12/80、实拍 1/66；JPEG-85 为
13/80、2/66；缩放恢复 PNG 为 5/80、0/66；截图式 PNG 为 8/80、0/66。WebP-85 原始数为生成图
11/80、实拍 1/66，但静态 WebP 本就不具备产品高置信资格。结果显示 DDA 在这个更新生成器确认窗的
传播代理上召回较低，且原图／JPEG 条件下出现实拍越阈值；它不支持调整运行时阈值、加大分值或把
低分解释为实拍证据。协议与报告为
`research/records/2026-08-20/pixel/dda_propagation_audit_protocol_v1.json` 和
`dda_propagation_audit_v1.json`，均保持 `deployment_eligible=false`。

### 2.4 新模型可能只是重复已有证据

一个候选即使单独准确率较高，如果只命中现有 SAFE、Community 或 forensic 已经命中的图片，就不会改善系统召回。反之，把多个相关纹理模型同时作为强证据，会使分数更快达到上限，却没有增加来源独立性。

下一轮必须把“当前五通道漏检中新增命中多少”作为主要指标，不能只比较候选自己的准确率、AUC 或论文排行榜。

## 3. 公开候选复核

### 3.1 已完成并淘汰：FerretNet

[FerretNet](https://github.com/xigua7105/FerretNet)通过预测局部像素邻域、再观察重建残差来暴露局部纹理不连续、边缘和颜色过渡异常。其论文发表于 NeurIPS 2025，代码仓库标注 Apache-2.0。

它被选为首个候选的原因：

1. 模型远小于 CLIP-L/14 一类通道，理论上适合单图 CPU 隔离进程；
2. 信号机制与现有语义 CLIP 不同，有机会补充现代生成器漏检；
3. AIGIBench 更新榜单中实拍准确率 96.6%、生成图准确率 61.8%，表现比 NPR、DFFreq 等轻量传统候选更均衡；
4. 官方已经发布预训练模型，具备复现实验的最低条件。

筛选实现中的必要安全边界：

1. 官方演示硬编码 `.cuda()`，并为 Grad-CAM 执行反向传播；Demirror 只能提取前向分类路径，不能原样调用；
2. 权重通过外部网盘发布，代码许可不自动等于权重许可；必须登记权重来源、授权说明、文件大小和 SHA-256；
3. 论文和榜单数字没有回答它对 Demirror 当前五通道漏检是否有增量；
4. 仍需验证 JPEG、截图式栅格化、缩放和 WebP 下是否保持方向一致；
5. 依赖清单未严格锁定，研究环境必须单独冻结，不能污染产品环境。

实际结果否决了它的模型有效性，而不是资源可行性：原图 1/80、JPEG-85 0/80 的更新生成图命中不足以通过任何预先登记的生成召回或增量门禁。原图和 JPEG 的二值结论高度一致（99.375%）在这里不是优点，而是“两个视图都基本没有检测到生成图”的一致。

### 3.2 第二优先：LOTA

[LOTA](https://github.com/hongsong-wang/LOTA)使用位平面引导模型关注容易被视觉内容掩盖的低位痕迹。代码仓库标注 MIT，AIGIBench 更新榜单中的实拍／生成图准确率为 89.3%／65.1%。

它对生成图的单模型召回略高于 FerretNet，但有两个明显风险：

- 10.7% 的实拍错误已经接近本项目可接受边界；
- JPEG、缩放、截图和平台重编码会直接改写低位平面，可能造成明显失效或方向翻转。

只有在 FerretNet 没有提供足够增量，或两者命中集合显示明显互补时，才值得投入 LOTA 的完整复现。

这项判断已进入**源码预检、尚未进入模型评测**阶段。固定的官方版本
`de2f70a5acc195cbb3cfedb1909d75343b1bd023` 根目录为 MIT 许可，但官方测试入口有多处
`.cuda()` 调用；更关键的是，模型构造器忽略其 `pretrain=False` 形参并仍调用
`resnet50(pretrained=True)`，会尝试模型库网络下载。Demirror 的预检适配器只在动态加载的
模块内临时将这一调用固定为 `pretrained=False`，未编辑官方源码，也没有加载 detector
checkpoint。CPU 合成前向通过并不弥补权重来源、许可、严格张量加载和跨变体增量均尚未验证
的缺口。

后续只有用户从作者提供位置取得原始 checkpoint、可记录文件大小与 SHA-256，并确认权重
使用条件后，才可另建不可变协议，进行原图、JPEG-85、WebP-85、缩放恢复和截图式 PNG 的
隔离评分。该评分仍必须以新增漏检命中、每生成器、独立实拍来源、变体稳定和资源上限联合
淘汰，不能把上述 CPU 冒烟当作接入资格。

### 3.3 暂缓候选

| 候选 | 公开表现或特点 | 暂缓原因 |
| --- | --- | --- |
| Effort | AIGIBench 实拍／生成图 96.9%／57.1%，CLIP-L/14 正交子空间 | 模型和运行时较重；官方仓库未见明确许可文件 |
| DFFreq | AIGIBench 91.8%／58.0%，频域检测 | 与现有频率／纹理通道可能相关；许可与单图入口不清晰 |
| GAPL | 生成器感知原型，论文报告六基准平均准确率 90.4% | 官方快速推理要求 CUDA，CLIP 骨干较重，许可仍需核验 |
| GlobalForge | 强调全局结构和退化稳定性 | 尚无稳定、可审计的正式代码和权重发布 |
| FIND | 噪声扰动训练，论文报告较高效率 | 当前没有找到可核验的官方代码和预训练权重 |
| PROBE-AIGI | 面向跨生成器能力诊断 | 更适合作为评估集和失效分析工具，不是直接部署的检测器 |

## 4. FerretNet 冻结淘汰筛选

### 4.1 实现边界

首轮只允许新增研究目录中的候选适配器，不进入 `src/image_trust` 的产品执行链：

1. 固定官方仓库提交；
2. 单独记录代码许可和权重许可，不把二者混为一项；
3. 对 checkpoint 做 SHA-256 和严格参数覆盖审计；
4. 只保留 forward-only 分类路径，移除 Grad-CAM、训练器和自动下载；
5. 使用 `sys.executable` 子进程、batch 1、CPU、固定线程数；
6. 单图超时、内存观测不可用、模型缺失或参数不匹配时失败关闭；
7. 不修改官方输出阈值进行首轮淘汰，避免在确认集上寻找漂亮操作点。

建议首轮资源止损：峰值工作集不超过 750 MiB，p95 单视图耗时不超过 5 秒，异常退出不能阻塞网页 worker。该上限是实验门禁，不是对官方速度声明的复述。

### 4.2 数据与变体

冻结来源至少包括：

- 较新生成器：现有 OpenFake 留出窗中的 FLUX.2、GPT Image、Midjourney、Z-Image 等来源；
- 独立实拍：MIT-Adobe FiveK、Google HDR+，以及取得官方清单后的 RAISE；
- 每个源图派生固定变体：原始解码、JPEG-85、WebP-85、长边缩放后恢复、截图式 PNG 栅格化；
- 同一源图的变体必须归为同一图簇，不能跨校准和确认 split。

平台真实转码和屏摄／打印再拍应作为后续独立门禁；首轮派生变体只能淘汰明显脆弱候选，不能替代真实传播评估。

### 4.3 停止条件

FerretNet 只有同时满足以下条件，才允许进入独立校准阶段：

1. **增量召回：**在当前五通道漏检的生成图中形成足够新增命中，而不是重复已有命中；
2. **跨生成器：**不能只依赖一个生成器切片，最弱登记切片也要有非零、可复核的增量；
3. **实拍边界：**每个独立实拍来源分别计算命中率和 Wilson 95% 上界，不能只合并出一个平均数；
4. **跨变体稳定：**JPEG、WebP、缩放和截图式栅格化不能出现大面积方向翻转；
5. **资源合格：**超时、峰值内存和残留子进程全部通过；
6. **可复现与许可：**代码、权重、依赖、输入清单和结果摘要闭合；权重用途不明确时不得进入产品。

若首轮失败，不在同一确认集上重选阈值、增广、投票或多裁切规则来“挽救”候选。任何新规则都必须成为新的预注册候选并使用新的留出数据。

## 5. 对现有产品的改进建议

### 5.1 短期不改计分

在 FerretNet 或其它候选通过独立门禁前，维持当前五通道、相关性预算和几何 0 分策略。公开榜单不能成为新增 10 分或 20 分的依据。

### 5.2 扩大评估覆盖比降低阈值更重要

下一轮数据投入优先级应为：

1. 完成 RAISE 独立相机来源；
2. 为当前五通道和候选统一生成 WebP、缩放、截图式栅格化变体；
3. 建立少量真实平台转码或再数字化控制；
4. 按生成器、实拍来源和变体分别报告，不只给总体数字。

这会直接暴露“原图有效、传播后失效”和“只对某一实拍来源误报”的规则，比继续调综合分更能提高实际可靠性。

### 5.3 保持证据分语义

在代表性校准集完成前，继续称为“AI 分数”或“证据分”，不要称为 AI 概率。后续若要校准概率，必须使用来源隔离、图簇隔离、未参与模型选择的最终留出集，并对不同传播条件分别检查校准误差。

## 6. 建议实施顺序

1. FerretNet 已完成资源探针和第一道原图／JPEG-85 淘汰筛选，按停止条件拒绝；不再运行其五变体或尝试事后调参。
2. LOTA 已完成不含 checkpoint 的 CPU 预检；上述四变体已经按不可变协议材料化。取得可核验的作者原始权重后，必须在这些固定视图上进行隔离评分；否则它很可能重演只在理想原图有效的情况。
3. 优先补足 RAISE 相机 RAW 对照和现实传输变体。这会同时提高对现有五通道与未来候选的判断质量。
4. 只有新候选同时补上现有漏检、通过独立实拍来源与传播变体门禁，才另建校准／确认 split，讨论是否计分。
